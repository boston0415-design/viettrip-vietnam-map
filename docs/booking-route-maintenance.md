# 예약·문의 경로 유지관리

설정일: 2026-09-18. 회원은 기존 업체 등록만 진행하며 예약 연락처를 조사하거나 입력할 필요가 없다. 운영 측 정기 점검 작업이 공식 예약·문의 경로를 조사하고 확인된 변경을 반영한다.

## 연결 대상

- 운영 지도: https://viettrip-vietnam-map.pages.dev/
- 저장소: `boston0415-design/viettrip-vietnam-map`, `main`
- 배포: GitHub main → Cloudflare Pages. README의 과거 Netlify 주소를 현재 운영 주소로 사용하지 않는다.
- 공개 업체 데이터: Supabase `oopxtadfimshydsskcyq`, `public.places`
- 예약 데이터: `assets/js/booking-links.js`의 `VERIFIED_BUSINESS_BOOKINGS`, `VERIFIED_BUSINESS_CONTACTS`
- 정기 작업: ‘베트남맵 예약 경로 업데이트’, 매일 베트남 시간 오전. 실시간 등록 이벤트 처리가 아니다.

## 조사 순서

1. 매 실행마다 현재 GitHub main과 공개 업체 목록을 읽는다. `id`, `name`, `category`, `address`를 기준으로 기존 확인 항목과 대조한다. 로컬 작업 폴더나 이전 실행의 목록을 최신으로 가정하지 않는다.
2. 신규 등록, 기존 이름·주소 변경, 예약 경로 미등록 업체를 우선한다. 이전 운영 기록과 대조하여 아직 조사하지 않은 업체부터 순환한다.
3. 공식 예약 홈페이지, Zalo 계정/ID, Facebook, Messenger, TikTok, 카카오톡, WhatsApp, 전화 등에서 실제 예약 또는 예약 문의 방법을 확인한다. 사이트나 계정의 존재만으로 예약 가능이라고 판단하지 않는다.
4. 기존 경로도 마지막 확인일이 오래된 순서로 재검토한다. 접속 장애 한 번을 폐업이나 연락처 폐기로 단정하지 않는다.
5. 검증 근거 URL, 정확한 지점, 확인 날짜, 결과를 간결한 운영 기록에 남긴다. 미확인 후보는 사유와 다음 점검 대상으로 기록하여 같은 검색만 반복하지 않는다.

## 확인 기준

- 업체명, 주소, 지점을 대조하고 운영자의 공식 출처에서 연락처 연결을 확인한다. 동명 업체, 팬 계정, 광고 대행사, 임의 숙소 호스트의 연락처를 연결하지 않는다.
- 브랜드 공통 계정은 문의할 지점을 명확하게 안내한다. 이름/주소 불일치는 업체 정보를 임의 수정하지 말고 미확인 사유로 기록한다.
- Zalo ID나 전화번호에서 계정 URL을 추측하지 않는다. 운영자가 제공한 목적지를 사용한다. 아이디만 확인되고 연결 주소가 없으면 주소가 있다고 주장하지 않는다.
- TikTok은 공식 프로필에 예약 문의 또는 예약 경로가 안내된 경우에만 추가한다. 일반 영상이나 짧은 공유 링크를 예약 버튼에 넣지 않는다. 프로필의 외부 예약 링크가 확인되면 그 실제 문의/예약 경로를 우선한다.
- Facebook/TikTok 로그인 또는 접근 제한 때문에 확인하지 못한 정보는 미확인으로 남긴다. 계정 접근 제한을 우회하지 않는다.
- 업소에 메시지 전송, 통화, 예약 또는 결제를 하지 않는다. 채널을 찾는 작업이며 이용자를 대신한 예약 행위가 아니다.

## 반영·검사

- 직접 예약 페이지는 ‘예약하기’, 연락 채널은 ‘예약 문의’로 표시한다. TikTok 연결은 ‘틱톡 예약 안내’로 표시하며 프로필에서 예약 안내를 확인하도록 한다.
- `verifiedBookingFor`의 업체 ID/이름/분류/주소 검증을 유지한다. 임의 입력이나 비슷한 상호에 링크가 자동 부여되지 않도록 한다.
- 기존 직접 예약과 교통 예약을 보존한다. 새 연락 채널에 맞는 안전한 URL 검증 및 실제 문의 화면을 점검한다.
- 변경된 예약 스크립트의 `index.html` 버전 문자열을 갱신한다. `tests/booking-inquiries.test.cjs`, `tests/booking-links.test.cjs`와 `node scripts/build-pages.mjs`로 관련 동작을 검사한다. 실제 브라우저/기기 검사를 하지 않았다면 한 것처럼 보고하지 않는다.
- 현재 main을 다시 확인하고 필요한 파일만 커밋한다. 강제 푸시, 로컬 전체 초기화, 다른 변경 덮어쓰기를 하지 않는다. Cloudflare Pages 배포 성공 및 운영 파일 반영까지 확인한 후 완료로 보고한다.
- 공개 운영 기록에는 필요한 업체 정보와 공개 출처만 남긴다. 사용자 비밀키나 회원 개인정보를 기록하지 않는다.

## 보고

변경된 업체나 새 문제만 한국어로 간결하게 알린다. 확인 날짜와 공식 근거를 포함하고 미확인 사항을 구분한다. 변경·새 문제 모두 없으면 알림을 보내지 않는다. 실행 권한이나 배포가 막히면 원인을 알리고 완료라고 표현하지 않는다.
